# 명세: 마커 클러스터링

- 작성일: 2026-08-20
- 상태: 구현됨

## 목표

`office-marker-bbox-sync` 명세는 "마커가 겹쳐도 그대로 둔다"고 범위 밖으로 미뤄뒀다. 실제로
줌 아웃하면(특히 트렁케이션 임계치 근처, bbox당 최대 500건) 마커 수백 개가 서로 겹쳐 사무소를
구분할 수 없다. 카카오 SDK의 `MarkerClusterer`로 인접 마커를 개수 배지로 묶어 보여주고,
확대하면 자동으로 풀리게 한다.

## 범위 밖

- **클러스터 아이콘·색상 커스터마이징** — 카카오 기본 클러스터 스타일을 그대로 쓴다.
- **클러스터 클릭 시 동작 커스터마이징** — 카카오 기본 동작(클릭한 클러스터 영역으로 자동 확대)을
  그대로 쓴다. 별도 핸들러를 달지 않는다.
- **개별 마커 클릭 → 사이드 패널** — 다음 명세(product-spec MVP 다음 항목).
- **오피스 조회·debounce·트렁케이션 로직 변경** — `office-marker-bbox-sync`가 이미 구현한
  `useOfficeMarkers`의 fetch/debounce 부분은 그대로 재사용한다. 이번 명세는 "마커를 어떻게
  지도에 붙이는가"만 바꾼다.
- **클러스터 임계 줌 레벨(`minLevel`)의 최종 확정** — 합리적인 기본값으로 시작해 브라우저에서
  실제 밀도로 확인하고 필요하면 조정한다. `DEFAULT_LEVEL`(지도 기본 줌, 현재 8이 너무 넓다는
  `docs/decisions.md`의 별도 미해결 항목)과는 독립적으로 다룬다.

## 수용 기준

**순수 로직** (Vitest 단위 테스트 — 실제 SDK 없이 `lib/kakaoMarkers` 어댑터를 모킹)

- [x] AC1: 카카오 스크립트 URL에 `libraries=clusterer` 쿼리가 포함된다 (`buildKakaoMapScriptUrl`
      기존 AC1 갱신 — 클러스터러는 별도 SDK 라이브러리라 로드 시점에 선언해야 한다).
- [x] AC2: 지도가 준비되면 클러스터러가 정확히 1번 생성된다 (오피스 목록이 여러 번 바뀌어도
      재생성되지 않는다).
- [x] AC3: 오피스 목록이 바뀌면 클러스터러에 새 마커 전체가 추가되고, 개별 마커는 `map`에
      직접 붙지 않는다 (마커의 지도 부착·해제는 클러스터러가 전담한다).
- [x] AC4: 언마운트되거나 오피스 목록이 다시 바뀌면, 그 시점까지 클러스터러에 추가돼 있던
      이전 마커 배치가 제거된다 (잔류 없음 — `office-marker-bbox-sync` AC7과 동일한 성격).

**컴포넌트 동작** (실제 카카오 SDK·DOM 필요 — `bun run dev` 브라우저 확인)

- [x] AC5: 마커가 조밀하게 모인 영역은 개별 핀 대신 숫자 배지가 있는 클러스터로 보인다.
- [x] AC6: 클러스터를 클릭하면 해당 영역으로 지도가 확대되며 클러스터가 풀린다.
- [x] AC7: 개별 마커가 구분될 만큼 확대하면 클러스터가 아닌 낱개 마커로 보이고, 마우스를
      올리면 사무소명이 노출된다 (`office-marker-bbox-sync` AC10 회귀 확인).
- [x] AC8: 지도를 이동해 오피스 목록이 갱신되면 클러스터도 새 목록 기준으로 다시 계산된다
      (이전 영역의 클러스터가 잔류하지 않는다 — AC7 회귀 확인).
- [x] AC9: `isTruncated` 안내 문구는 클러스터링과 무관하게 그대로 동작한다 (회귀 확인).

## 영향 범위

- **만질 파일**
  - `apps/web/lib/kakaoMapSdk.ts` — `buildKakaoMapScriptUrl`에 `libraries=clusterer` 쿼리 추가
  - `apps/web/__tests__/unit/kakaoMapSdk.test.ts` — AC1 갱신(기존 단정문에 라이브러리 쿼리 확인 추가)
  - `apps/web/lib/kakaoMarkers.ts` — `createOfficeMarker`에서 `map` 옵션 제거(클러스터러가
    부착을 전담하므로), `createMarkerClusterer(map)` 신규 추가. `removeMarker`는 더 이상
    쓰이지 않아 제거
  - `apps/web/hooks/useOfficeMarkers.ts` — 클러스터러를 `map` 마운트 시 1번 생성해 `useRef`로
    들고, 오피스 목록이 바뀔 때마다 `clusterer.addMarkers`/`removeMarkers`로 교체
  - `apps/web/types/kakao.d.ts` — `MarkerClusterer` 클래스·옵션 타입 추가
  - `apps/web/__tests__/unit/useOfficeMarkers.test.ts` — 마커 모킹 대상을 클러스터러 어댑터로 교체
- **새 의존성**: 없음 (카카오 SDK의 `clusterer` 라이브러리는 스크립트 쿼리 파라미터로 로드 —
  npm 패키지 아님)
- **기존 기능 영향**: `office-marker-bbox-sync`의 마커 부착 방식이 바뀐다(직접 `setMap` →
  클러스터러 경유). fetch/debounce/트렁케이션 로직은 무변경.

## 설계 메모

- **레이어**: 클러스터러 생성·마커 추가/제거도 `lib/kakaoMarkers.ts`(SDK 어댑터) 안에 둔다 —
  `office-marker-bbox-sync`에서 세운 "훅은 어댑터를 통해서만 SDK를 만진다" 경계를 그대로 따른다.
- **클러스터러 생명주기**: 마커와 달리 클러스터러 자체는 오피스 목록이 바뀔 때마다 새로 만들지
  않는다 — `map`이 바뀔 때(사실상 마운트 시 1번) 생성해 `useRef`에 보관하고, 오피스가 바뀌면
  그 인스턴스에 마커만 교체한다. 매번 재생성하면 클러스터 애니메이션·상태가 끊긴다.
- **`minLevel` 기본값**: 카카오 공식 예제가 흔히 쓰는 값(6)에서 시작해 실제 시딩 데이터
  밀도로 브라우저 확인 후 필요하면 조정한다 — `office-marker-bbox-sync`에서 z-index·CORS를
  그렇게 잡았던 것과 같은 방식.

## 실행 결과 (브라우저 검증, 2026-08-20)

- **AC1~AC4**: Vitest 16개 통과(신규/갱신 7건 + 기존 9건 회귀 없음).
- **AC5~AC9**: 로컬 Postgres에 조밀 클러스터 30건 + 개별 2건을 임시로 넣고 `bun run dev`
  브라우저로 확인.
  - **AC5**: 초기 화면(레벨 8)에서 30건이 "30" 숫자 배지 클러스터로 보였다. `minLevel: 6`
    기본값을 별도 조정 없이 그대로 써도 이번 밀도에서는 잘 맞았다.
  - **AC6**: 클러스터 클릭 → 지도가 확대됨. 카카오 클러스터러 기본 동작은 클릭 시 "완전히
    풀리는 레벨"까지 한 번에 가는 게 아니라 단계적으로 확대돼, 이번 데이터 분포(반경 약
    200m)에서는 2번 클릭 후 완전히 풀렸다. 스펙엔 "확대되며 풀린다"고만 적었고 클릭 횟수는
    명시하지 않았으므로 이 동작 그대로 충족으로 판단.
  - **AC7**: 완전히 확대된 상태에서 30개 마커 각각에 `title` 속성(사무소명)이 정상 존재함을
    DOM에서 확인. `office-marker-bbox-sync` AC10 회귀 없음.
  - **AC8**: 클러스터 영역에서 데이터가 없는 지역(안산·군포 방면)으로 크게 이동 → 클러스터·
    마커가 잔류 없이 완전히 사라지고, 새 bbox로 정상 재조회됨을 네트워크 로그로 확인.
  - **AC9**: 이번 명세는 `KakaoMap.tsx`(트렁케이션 문구 렌더 위치)를 전혀 건드리지 않았다
    (`git status`로 확인) — 코드 변경이 없으므로 office-marker-bbox-sync에서 이미 검증한
    동작이 그대로 유지된다고 보고, 별도 재현은 생략했다.
  - 콘솔에 CORS 관련 에러 로그가 몇 줄 남아 있었으나, 네트워크 로그로 확인한 결과 이전
    브라우저 세션(오늘 앞선 명세 검증)에서 누적된 과거 로그였다 — 이번 조회는 전부 200 OK.
  - 이번에도 카카오 도메인 미등록(`docs/decisions.md` 미해결 항목) 문제로 원본 저장소의
    `app-web`을 사용자 승인 하에 잠시 내렸다가 검증 후 정상 복구했다.
